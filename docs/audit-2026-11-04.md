# GoGetCards — production audit, 2026-11-04

Scope: the live site https://gogetcards.com and this repository, audited
against Google Merchant Center policy (Shopping ads and free listings,
Misrepresentation, product data specification, landing page, checkout,
shipping and returns requirements), technical SEO, Core Web Vitals,
OWASP-style security, conversion readiness, Google Ads / GA4 readiness,
feed and catalogue data, accessibility and operational reliability.

Method: five parallel read-only investigations (crawl of all 171 sitemap
URLs as Googlebot and as Chrome; Lighthouse 13.6 mobile/desktop; code
review of every route, model, service and template; the live feed and all
142 product pages parsed and cross-checked; the checkout and order
pipeline traced end to end) followed by fixes, each verified by the
repository's own test suites and audit scripts and then on the deployed
site. No orders were placed and no charges were made. There is no database
access from this environment, so anything that lives only in the database
(Distribution selection mode, individual product records) is reported from
what the live pages and feed show and flagged where it needs confirming.

Git checkpoint before any change: tag `audit-checkpoint-2026-11-04`
(commit 525e62d). Changes: commits 48fa647, ed54832, 9a51a6a, c9a5d62 and
the follow-up noted in section G. Every change is on `main` and deployed.

## A. Executive summary

The store is technically in good shape for a Merchant Center review, with
one important caveat that only you can resolve (the business address, see
H1) and one operational item that must be set before advertising (the
feed currently lists 4 of 142 products, H2).

What was wrong and is now fixed on the live site:

- **Three different preorder dispatch windows were live at once**
  ("ships release day" on the homepage and preorders collection, "release
  day or the business day after" in the Preorder Policy and product terms,
  "within 2 business days" on the Shipping page, which is what Merchant
  Center holds). Every surface now reads one configured number.
- **The Shipping page contradicted the Refund policy** on change-of-mind
  return postage (paid by buyer vs free). Both now derive from one flag,
  and match the free prepaid-label setting in Merchant Center.
- **The old Shopify URLs** (`/pages/returns-refunds`, `/pages/shipping-policy`,
  `/pages/pre-order-faq`, `/policies/*`, `/collections/x/products/y`,
  `/search`, `/account/login`) 404'd. No legacy content was live, but a
  reviewer following an indexed link landed on nothing. All now 301 to the
  page holding the same information.
- **Landing-page price mismatch on 62 pack-priced products**: the headline
  price was a rounded per-unit figure while the feed and structured data
  carried the pack price. The pack price is now the headline everywhere.
- **Preorders never expired**: with 37 release dates landing this month, the
  feed would have sent `preorder` with a past `availability_date` (an item
  error) and pages would have said "not yet released" after release. A
  preorder is now one whose date has not arrived; the first one
  (Cosmic Chrome Baseball, 2026-11-04) already reads In Stock live.
- **An unauthenticated endpoint could create paid orders** (a Shopify-era
  `/api/track-order`). Removed; a static test now permits Order creation in
  exactly one place, behind the HMAC verifier.
- **Stock never followed a sale**, so the last unit could be sold twice.
  Paid orders now decrement stock atomically; the checkout caps at counted
  stock; an oversold order is stamped for the admin.
- **Mobile CLS of 0.39 on collection pages**, a cookie banner that was the
  LCP element and waited for the JS bundle, a parser-blocking bundle, and
  cache versions that reset on every restart are fixed.
- Soft-404 collection URLs, indexable 404 pages, trailing-slash duplicates,
  `npm audit` back to 0, a committed reCAPTCHA secret fallback, seeded
  default admin password, error details in responses, missing SSRF checks
  and several accessibility failures are fixed.

What is not done and needs you (section H): confirm or replace the
El Segundo address; set the feed selection so the whole catalogue is
listed; set the Google Ads / GA4 ids and the reCAPTCHA secret in the
platform environment; add images for 3 products and GTINs for 74; decide
on real stock counts; move product images off third-party Shopify CDNs.

## C. Risk classification

**Critical (fixed)**
- Unauthenticated paid-Order creation (`/api/track-order`). Fixed: removed.
- Stock never decremented → unbounded overselling. Fixed: atomic ledger.

**Critical (needs you)**
- Business address accuracy (H1). Not fixable from here.

**High (fixed)**
- Preorder dispatch window stated three ways; shipping/refund contradiction.
- Pack-product landing-page price mismatch (62 products).
- Preorders never expiring by date (37 releases this month).
- Anyone could enrol any email in the recovery email sequence with a
  chosen shipping address; recovery link skipped address confirmation.
- Replayed thank-you link signed the customer in again.
- Soft-404 collection URLs (unbounded indexable junk).
- Collection-page CLS 0.39 on mobile (fails Core Web Vitals).
- npm audit 4 moderate (minimatch via ejs/jake) → 0.

**High (needs you)**
- Feed lists 4 of 142 products (H2).
- No Google Ads / GA4 tag ids set in the environment: nothing is tracked.
- Product images on third-party Shopify CDNs.

**Medium (fixed)**
- Cross-site write guard (CSRF defence beyond SameSite); x-powered-by.
- Committed reCAPTCHA secret fallback; seeded `changeme123` admin.
- err.message / err.stack in 20+ responses; `/admin/test-error`.
- Unsigned `/thank-you` rendered a receipt for any URL values.
- Client IP from spoofable leftmost X-Forwarded-For (analytics/geo).
- SSRF: admin-supplied URLs fetched without target validation.
- Indexable 404 pages; trailing-slash duplicates; cart page not noindex.
- Cache version reset on every restart; `no-store` broke bfcache.
- Chat widget polled every 3 s on the shared API limit.
- reCAPTCHA (360 KB) loaded for every contact-page visitor.

**Medium (needs you / not done)**
- 74 products without GTIN; 3 without images.
- Admin 2FA exists in settings but is not enforced at login (removed at
  your request earlier). Re-enable only if you have the authenticator.
- Checkout/abandoned rows have no TTL (PII retained indefinitely).
- Automated backups: none scheduled (`scripts/backup.js` is manual).
- Enhanced conversions not sent (pooled-email mode makes the hashed
  email unreliable).

**Low (fixed)**: focus rings, hamburger size, link underlines, pagination
contrast, cart drawer aria/focus, chat aria, Organization image, footer
social hrefs, feed key constant-time compare, body-value coercion.

**Low (open)**: long `<title>`s on ~58 pages (One Piece suffixes);
`/releases?line=` indexable variants; `connect.sid` cookie name;
`saveUninitialized` sessions for crawlers; CSP without `script-src`
